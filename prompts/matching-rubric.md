# Job-to-CV Matching Rubric

## Required Requirements Analysis

For each requirement marked "required" in the job description:

1. **Search the career document** for direct matches
2. **Check for transferable skills** (similar but not identical)
3. **Assess adjacent skills** that could bridge the gap with ramp-up time
4. **Flag gaps** if no evidence exists

**Confidence scoring:**
- DIRECT (100%): Exact match in recent role, explicitly listed
- TRANSFERABLE (70%): Similar skill demonstrated, requires adaptation
- ADJACENT (40%): Related skill that transfers with learning curve
- GAP (0%): No evidence in career document

## Preferred Requirements Analysis

For each requirement marked "preferred" or "nice-to-have":

1. **Mark coverage** if present (DIRECT or TRANSFERABLE)
2. **Note absence** without penalty if missing
3. **Highlight strengths** if exceeds requirement

## Experience Requirement Matching

**Years of experience:**
- Extract required years from job description (e.g., "5+ years")
- Compare to career document roles and tenure
- Count directly relevant experience only
- **Transferable time**: Experience in adjacent domains/roles (0.5x multiplier)
- Flag if shortfall is significant (>2 years gap)

**Seniority level:**
- Map job level (IC/Senior/Lead/Manager) to career document roles
- Assess scope growth and progression
- Flag if candidate appears over/under-qualified

## Technology Stack Matching

**Exact matches:**
- List frameworks, languages, tools explicitly in career document
- Each match increases confidence

**Near matches:**
- Same paradigm (e.g., React ≈ Vue, Python ≈ Ruby)
- Same domain (e.g., relational DBs: PostgreSQL, MySQL, Oracle)
- Rate as TRANSFERABLE

**Missing stack:**
- Technologies new to candidate
- Rate as ADJACENT or GAP depending on learning curve
- Flag as potential ramp-up time

## Industry/Domain Matching

**Regulated domains** (healthcare, finance, legal, government):
- Flag if career document shows exposure
- Flag if candidate new to regulated contexts
- This is context-dependent (STRETCH if new)

**Emerging tech** (AI/ML, blockchain, quantum):
- Assess proof of learning (courses, projects, patents)
- Flag if bleeding-edge vs. established tech

**B2B vs B2C:**
- Note if applicant's experience is opposite
- Not a disqualifier but flag for context switching

## Strength Identification

**Top strengths to highlight:**
1. Direct matches that exceed requirements
2. Relevant achievements that solve the job's problems
3. Seniority/scope match or growth
4. Unique combinations of skills (e.g., design + engineering)
5. Relevant certifications or recognitions

**Positioning angles:**
- **Systems & Engineering**: Emphasize architecture, scale, cross-team work
- **Regulated Industries**: Emphasize compliance, audits, risk management
- **Design Ops & Leadership**: Emphasize team growth, process design, stakeholder management
- **AI & Emerging**: Emphasize innovation, research, emerging tech adoption

## Gap Categorization

**Skill gaps:**
- **Hard skills**: Languages, frameworks, tools (ramp-up: 2-12 weeks)
- **Domain knowledge**: Industry-specific practices (ramp-up: 4-16 weeks)
- **Soft gaps**: Certifications, degrees (ramp-up: varies)

**Experience gaps:**
- **Years shortfall**: e.g., need 5, have 3 (gap: 2 years)
- **Scope gap**: e.g., need to manage 10 people, have managed 3
- **Context gap**: e.g., new to regulated domain, new to startup environment

**Red flags:**
- Deal-breaker gaps (e.g., required certification not obtainable)
- Learning curve too steep for timeline (if candidate starting immediately)
- Significant scope mismatch (too junior or overqualified)
- Unexplained career breaks or pattern mismatches

## Terminology Mapping

Create a glossary of **job description terminology → candidate background equivalents**:

Example:
```
"Full-stack engineer" → Frontend + Backend role
"Startup experience" → Scrappy execution, wearing multiple hats
"Work at scale" → Handled >1M users, complex infrastructure
"Product thinking" → Collaborated on feature decisions, user research
```

This helps frame the candidate's background in terms the employer will understand.
